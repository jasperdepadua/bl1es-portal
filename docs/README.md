# docs/

Operational how-tos for local development — setting up third-party tools/services needed to run or
test the app. Distinct from `plan/` (point-in-time feature implementation plans) and `specs/`
(business rules) — this is "how do I get X working on my machine," not "why does X work this way."

- **`mailtrap-setup.md`** — email-testing sandbox used by the Management sub-project's invite-link
  flow (register a teacher/student → receive their setup link) during development.
